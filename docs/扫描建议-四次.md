## 2. 本轮新发现

### 2.1 【P2】hilog 的行高估算与行距不一致,滚到底部会空出一大片

- **位置**:`apps/fhdc-desktop/src/panels/hilog.rs:374-381`
- **现象**:日志面板滚到底部时,最后几行挤在视口上方,下面留出大片空白;日志越多空白越大,滚动条也明显偏短。行数上千时,滚到底看到的有效内容只占视口的上 2/3。
- **原因**:`show_rows` 的行距是用**调用它的那个 `ui` 的 `item_spacing`** 算的。egui 0.33.3 的实现(`scroll_area.rs`):

  ```rust
  let spacing = ui.spacing().item_spacing;
  let row_height_with_spacing = row_height_sans_spacing + spacing.y;
  self.show_viewport(ui, |ui, viewport| {
      ui.set_height((row_height_with_spacing * total_rows as f32 - spacing.y).at_least(0.0));
  ```

  终端面板把 `item_spacing.y = 0` 设在了 `show_rows` **之前**(`shell.rs:337`),所以算出来的行距 = 字体行高,和实际渲染一致 —— 这是对的。

  hilog 把同一句放进了 `frame.show(ui, |ui| ...)` 内部(`hilog.rs:381`),而那个 `ui` 是 `show_rows` 闭包里的子 `ui`。于是在计算行距时读到的仍然是全局的 `8.0`:

  | | 计算用行距 | 实际渲染行距 |
  | --- | --- | --- |
  | 终端 | ≈15.5 + 0 = 15.5 | 15.5 |
  | hilog | ≈15.5 + 8 = **23.5** | **15.5** |

  内容高度按 23.5 估、实际只有 15.5,每行虚高 8px。500 行就是约 4000px 的幻影滚动区。上一版这里用的是常量 `ROW_HEIGHT = 17.0`,只差 1.5px/行,几乎看不出来 —— 这轮把间距清零放进子 `ui` 之后,误差从 1.5px 放大到 8px,反而更明显了。

- **改法**:把 `frame` 提到 `show_rows` 外面,和终端保持同构(这是最干净的):

```diff
         let stick = self.auto_scroll;
+        let frame = egui::Frame::new()
+            .fill(palette.terminal_bg)
+            .corner_radius(4.0)
+            .inner_margin(6.0);
+        frame.show(ui, |ui| {
+            ui.spacing_mut().item_spacing.y = 0.0;   // ← 必须在 show_rows 之前
+            ui.style_mut().override_text_style = Some(egui::TextStyle::Monospace);
+            let font_id = egui::TextStyle::Monospace.resolve(ui.style());
+            let row_height = ui.fonts_mut(|fonts| fonts.row_height(&font_id));
+            ui.set_min_width(ui.available_width());
+            egui::ScrollArea::vertical()
+                .auto_shrink([false, true])
+                .stick_to_bottom(stick)
+                .show_rows(ui, row_height, visible_len, |ui, range| {
+                    for index in range {
+                        // ... 原样搬进来
+                    }
+                });
+        });
```

> 只挪 `item_spacing` 那一句、不挪 frame 行不行?不行 —— 间距必须在 `show_rows` 的**调用方** `ui` 上清零,而那层 `ui` 只在 frame 外面能拿到。

- **验收**:日志攒到几百行,「自动滚动」开着,滚到底 —— 最后一行应贴着视口底部,下方不应有空白。

### 2.2 【P3】跨块的 CRLF 会变成两个换行

- **位置**:`apps/fhdc-desktop/src/panels/shell.rs` `strip_ansi_stream`
- **现象**:极小概率下,终端里多出一个空行。
- **原因**:`\r` 分支判断 `chars.get(index + 1) == Some(&'\n')`;当分片正好切在 `\r` 和 `\n` 之间时,`get(index+1)` 返回 `None`,于是按"孤立 CR"处理,输出一个 `\n`;下一块的 `\n` 再原样输出一个。旧版按块清洗时也有同样行为,但现在既然已经为转义序列做了跨块续接,顺手把 CR 也续上更一致。

```rust
} else if ch == '\r' {
    if chars.get(index + 1) == Some(&'\n') { index += 2; }
    else if index + 1 == chars.len() {
        break;                       // ← 末尾的孤立 CR:留到下一块判断是不是 CRLF
    } else { index += 1; }
    output.push('\n');
}
```

> 注意 `break` 之前不能 push,且 `pending` 会从 `index` 开始保留 `\r`,下一块拼上如果是 `\n` 就整对吃掉。

### 2.3 【P3】`ansi_pending` 没有上限

- **位置**:`apps/fhdc-desktop/src/panels/shell.rs` `strip_ansi_stream`
- **现象**:理论上,一个永不结束的畸形转义序列会让 `ansi_pending` 一直吃字节,并且这段输入完全不显示。
- **原因**:`break` 时把 `chars[index..]` 全部存进 `pending`,没有任何上限。正常的 CSI/OSC 很快就会终止,`cat` 二进制时也确实可能在 ESC 之后很久才碰到 0x40–0x7E 的终止字节。
- **改法**:在 `strip_ansi_stream` 开头加一道保险 —— 待续接超过 4KB 就直接当普通文本吐出去,不再等终止符:

```rust
if pending.len() > 4096 {
    // 畸形转义:放弃续接,按字面量输出,避免吞掉后续内容。
    let literal = std::mem::take(pending);
    ...
}
```

### 2.4 【P3】连接成功后的自动选中存在竞态

- **位置**:`apps/fhdc-desktop/src/app.rs`(`EndpointConnectFinished` → `pending_select`)+ `runtime.rs`(连接成功后立刻 `Rediscover`)
- **现象**:网络连接成功后,下拉框偶尔不会自动选中刚连上的设备,得手动点一下。
- **原因**:本轮让连接成功后**立刻**重发现,于是 `DevicesChanged`(新设备已在列表里)可能先于 `EndpointConnectFinished` 被 UI 处理。此时 `pending_select` 还没设;等 `EndpointConnectFinished` 把它设上,因为快照已无变化(`broadcast_if_changed` 会跳过),不会再有 `DevicesChanged` 来触发 `apply_snapshot`,`pending_select` 就一直挂着直到 15 秒超时被清掉。

  在真实后端下,`hdc tconn` 回来后事件入队比一次发现往返快,所以多数情况顺序是对的;假后端(发现瞬时完成)更容易撞上。

- **改法**:`EndpointConnectFinished` 里先看一眼当前快照,已经在就直接选,不要干等下一次广播:

```rust
BackendEvent::EndpointConnectFinished { endpoint, message } => {
    self.show_toast(format!("连接成功: {message}"));
    self.remember_endpoint(endpoint.clone());
    if let Ok(key) = ConnectKey::new(endpoint.target_string()) {
        if self.snapshot.devices.iter().any(|r| r.descriptor.key == key) {
            self.send(BackendCommand::SelectDevice { key: Some(key) });
        } else {
            self.pending_select = Some((key, Instant::now()));
        }
    }
}
```

### 2.5 【P3】「清屏」没有重置 UTF-8 残片

- **位置**:`apps/fhdc-desktop/src/panels/shell.rs` 清屏按钮 → `clear_display()`
- **现象**:极小概率下,清屏后第一行开头多一个乱码字符。
- **原因**:`clear_display()` 清了 `tail` / `pending_line` / `ansi_pending`,但没有清 `utf8` 解码器里可能残留的半个字符。hilog 的「清空」上一轮已经补过这一句,终端这边漏了。
- **改法**:清屏按钮里补一行 `self.utf8 = super::Utf8Accumulator::new();`,或者干脆把两句都收进 `clear_display()`(`reset_for` 里那句就可以删掉)。

### 2.6 【建议】`DirectoryLoaded` 也该走统一入口

- **位置**:`apps/fhdc-desktop/src/panels/files.rs` `handle_event`
- **现状**:`reset_for` / `navigate` 已经统一走 `invalidate_entries()`,但 `DirectoryLoaded` 仍然是

  ```rust
  self.entries = entries.clone();
  self.entries_generation += 1;
  ```

  逻辑是对的(代次确实递增了),但绕开了刚建立起来的入口。下次再加一条修改 `entries` 的路径,很容易又漏掉缓存失效 —— 这正是前两轮连踩两次的坑。
- **建议**:加一个 `set_entries(Vec<RemoteFileEntry>)`,内部赋值 + 清缓存 + 递增代次,`DirectoryLoaded` 改调它。这样 `entries` 的写入口只有一个,`invalidate_entries()` 退化成 `set_entries(Vec::new())` 即可。

### 2.7 【NIT】`strip_ansi_stream` 每块多一次 `Vec<char>` 分配

- 每个分片先把 `pending + input` 收集成 `Vec<char>`(8KB 块约 32KB 内存),再逐字符扫描。旧实现用 `chars.peekable()` 是零拷贝。
- 高频输出时这是每秒几十次的临时分配,可接受;真要抠,可以改成按 `&str` 的 `char_indices()` 遍历 + 记录字节偏移。**不影响正确性,可以不动**。
