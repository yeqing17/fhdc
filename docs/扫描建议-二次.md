## 2. 本轮新发现

### 2.1 【P0】设备列表每 2 秒重新洗牌

- **位置**:`crates/fhdc-device/src/lib.rs:84` `snapshot()` + `apps/fhdc-desktop/src/runtime.rs:119`(周期间隔)
- **现象**:设备下拉框、连接管理窗口里的设备顺序**每 2 秒变一次**。鼠标悬在某个设备上准备点,列表在脚下换了位置;设备一多基本没法点。
- **原因**:两处改动叠加出来的。
  1. `snapshot()` 用 `self.records.values().cloned().collect()`,`HashMap` 的迭代顺序由随机种子决定,**每次调用都不同**;
  2. 新加的设备轮询每 2 秒调一次 `refresh_devices` → `reconcile` → `snapshot()`,并**无条件**广播 `DevicesChanged`。

  上一轮这个缺陷只在手点「刷新」时出现,频率低、不容易察觉;现在变成了每秒半次的持续抖动。
- **改法**:在 `snapshot()` 里排序,让同一组设备永远得到同一个顺序。

```diff
     pub fn snapshot(&self) -> DeviceSnapshot {
+        let mut devices: Vec<DeviceRecord> = self.records.values().cloned().collect();
+        // HashMap 迭代顺序不稳定;轮询每 2 秒重建一次快照,必须排序后才不会抖动。
+        devices.sort_by(|a, b| a.descriptor.key.cmp(&b.descriptor.key));
         DeviceSnapshot {
-            devices: self.records.values().cloned().collect(),
+            devices,
             selected: self.selected.clone(),
         }
     }
```

> 可选增强:在线设备置顶。
> `devices.sort_by(|a, b| b.descriptor.state.is_online().cmp(&a.descriptor.state.is_online()).then(a.descriptor.key.cmp(&b.descriptor.key)));`

**验收**:挂着界面 30 秒,下拉框顺序不应有任何变化。

### 2.2 【P1】设备轮询在命令循环里同步 await,可能堵住队列

- **位置**:`apps/fhdc-desktop/src/runtime.rs:126`
- **现象**:平时无感(一次 `hdc list targets` 几十毫秒)。但 `hdc` 卡住/服务器半死时,`list_devices` 会吃满 `DEFAULT_TIMEOUT`(8 秒),这段时间里**每 2 秒就有一次 8 秒的停顿**,点任何按钮都没反应,和上一轮 2.2 描述的症状一模一样 —— 只是源头从 `tconn` 换成了轮询。
- **原因**:`discovery_tick.tick()` 分支里直接 `.await refresh_devices(...)`,而 `refresh_devices` 内部要跑一条 hdc 命令。

```rust
_ = discovery_tick.tick() => {
    refresh_devices(&transport, &mut registry, &event_tx, &context).await;  // ← 阻塞直到 hdc 返回
    continue;
}
```

- **改法**:把"发现"也变成一个后台任务,结果回到主循环再处理。这样 `&mut registry` 仍然只由主循环持有,队列不会停。建议把上一轮 2.2 提过的 `done_rx` 扩成枚举,一次解决两类问题:

```rust
enum Completion {
    TransferDone(OperationId),
    /// 发现任务完成,带回最新设备列表。
    Discovered(Vec<DeviceDescriptor>),
}

// 主循环
_ = discovery_tick.tick() => {
    if !discovery_in_flight {
        discovery_in_flight = true;
        let transport = Arc::clone(&transport);
        let done_tx = done_tx.clone();
        tokio::spawn(async move {
            let descriptors = transport.list_devices().await.unwrap_or_default();
            let _ = done_tx.send(Completion::Discovered(descriptors)).await;
        });
    }
}
// done_rx 分支:Discovered(list) => { registry.reconcile(list); discovery_in_flight = false; ... }
```

代价是 `reconcile` 的错误信息会丢(`list_devices` 失败被吞成空列表,进而把设备全清空)—— 所以 `Completion::Discovered` 里应该带 `Result`,失败时保留上一次快照、只打一条日志。

**如果暂时不想动结构**,最小缓解:把 `DEVICE_POLL_INTERVAL` 调到 5 秒,并接受偶发卡顿。

### 2.3 【P2】`interval` 首跳立即触发,启动时多跑一次发现

- **位置**:`apps/fhdc-desktop/src/runtime.rs:119`
- **现象**:启动时紧跟着 `refresh_devices(...)` 之后(第 121 行),`interval` 的第一次 `tick()` 立刻完成,再来一次。两条 `hdc list targets` 背靠背。
- **原因**:`tokio::time::interval` 的约定就是"第一次 tick 立即就绪"。
- **改法**:

```diff
-    let mut discovery_tick = tokio::time::interval(DEVICE_POLL_INTERVAL);
+    // interval 的首个 tick 会立即触发,这里显式推迟一个周期,避免启动时连发两次。
+    let mut discovery_tick = tokio::time::interval_at(
+        tokio::time::Instant::now() + DEVICE_POLL_INTERVAL,
+        DEVICE_POLL_INTERVAL,
+    );
```

### 2.4 【P2】错误横幅每 2 秒重新弹出来

- **位置**:`apps/fhdc-desktop/src/app.rs` `handle_app_event`(`OperationFailed` → `last_error`)+ 轮询
- **现象**:hdc 服务器异常时,用户点「关闭」关掉错误条,2 秒后它又回来了,永远关不掉。
- **原因**:以前 `refresh_devices` 只在用户手动刷新时跑;现在每 2 秒跑一次,失败就每 2 秒发一条 `OperationFailed`。
- **改法**(二选一):
  1. 后端记住上一次的快照,内容没变就**不发** `DevicesChanged`(顺带也解决 2.5);失败时用单独的低优先级事件或只打日志,不要走 `last_error`;
  2. UI 侧给 `last_error` 加"相同文案 30 秒内不重复弹"的去抖。

推荐 1,顺带把每 2 秒一次的无谓重绘也省掉。

### 2.5 【P2】`DevicesChanged` 无条件广播

- **位置**:`apps/fhdc-desktop/src/runtime.rs:126` → `refresh_devices`
- **现象**:设备没变,每 2 秒仍然发一次全量快照 + `request_repaint()`,界面常驻 0.5 Hz 唤醒。
- **改法**:`DeviceSnapshot` 已经 `derive(PartialEq)`,`registry.reconcile` 之后比较一下,相同就不发事件:

```rust
let snapshot = registry.reconcile(descriptors);
if Some(&snapshot) != last_snapshot.as_ref() {
    last_snapshot = Some(snapshot.clone());
    send_event(event_tx, context, BackendEvent::DevicesChanged(snapshot)).await;
}
```

### 2.6 【P3】文件面板每行每帧多一次 `format!`

- **位置**:`apps/fhdc-desktop/src/panels/files.rs`(图标并入名称的那处)
- **现象**:目录里文件多时,每帧为每一行分配一个 `String`。
- **原因**:为了合并图标列,把 `RichText::new(&entry.name)` 改成了 `format!("{icon} {}", entry.name)`。
- **改法**:要么接受(目录通常几百项,可忽略),要么把拼好的显示名缓存进 `RemoteFileEntry` 的平行结构。**不建议**为此重构,记录在案即可。

### 2.7 【P3】「类型 / 用户」表头用了无边框 Button

- **位置**:`panels/files.rs`、`panels/processes.rs`
- **现象**:表头看起来可点,悬停有高亮,点了没反应。
- **原因**:用 `egui::Button::new(...).frame(false)` 代替了不可交互的 `ui.label`。
- **改法**:`ui.label(egui::RichText::new("类型").weak().small())` 即可,顺手去掉一个无意义的交互热区。

### 2.8 【P3】hilog「清空」没有重置增量解码器

- **位置**:`panels/hilog.rs` `show()` 的清空按钮

- **改法**:清空时一并 `self.utf8 = super::Utf8Accumulator::new();`(和 `reset_for` 一致)。

hdc -t <key> shell "sh -c '<LIST_SCRIPT 原文>' fhdc-files /data/local/tmp" | Format-Hex
